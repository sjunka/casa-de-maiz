# 12. Platform-native presentation: iOS glass, Android Material

## Status
Accepted

## Context
[[0010-styling-approach]] already commits to platform-specific files "where the difference genuinely improves the experience," but until now the Android build was pixel-identical to iOS: no `Platform.select` in presentation code, no ripple on any `Pressable`. The bonus brief asks for a tasteful iOS glass treatment and a distinct Android Material adaptation, not a palette swap.

## Decision
**iOS.** The tab bar background and the top-placement `AlertBanner` render over a real `UIVisualEffectView` material via `@react-native-community/blur`'s `BlurView` (ships Fabric codegen; verified to build against RN 0.86 New Architecture, so the ADR 0008-style contingency of a hand-written Fabric fallback was not needed). Both are wrapped by a shared `GlassSurface` component (`src/ui/GlassSurface.tsx`) that checks `useReduceTransparency` — a hook copying the shape of `useReducedMotion`, backed by `AccessibilityInfo.isReduceTransparencyEnabled()` and a `reduceTransparencyChanged` listener — and swaps the blur for an opaque surface, live, whenever the setting changes rather than only at mount. Cards remain opaque throughout; only the tab bar and the alert banner get the material.

**Android.** Material conventions are applied structurally:
- A single shared `AppPressable` (`src/ui/AppPressable.tsx`) replaces every raw `Pressable` call site. It sets `android_ripple` on Android and an opacity-on-press style on iOS, so all interactive elements changed together instead of one at a time.
- `ColorTokens` gained `surfaceElevated` plus a `getElevatedSurfaceStyle` helper (`src/theme/tokens.ts`) that resolves per platform: a tonal `surfaceElevated` background with `elevation` on Android, a hairline border and soft shadow on iOS. Components ask the token layer for elevation rather than branching on `Platform.OS` themselves.
- `@react-navigation/bottom-tabs` has no built-in Material 3 active-tab indicator, so both platforms get a fully custom `tabBar` (`src/navigation/AppTabBar.tsx`): icon-only, each tab an `AppPressable`, the focused tab marked by a top indicator line rather than a filled pill or a label. iOS and Android intentionally share this structure — only the material behind it diverges (glass on iOS via `GlassSurface`, a tonal `surfaceElevated` background with `elevation` on Android) and only the press feedback diverges (`AppPressable`'s ripple vs. opacity).
- Cards get a lighter version of the tab bar's material split: iOS renders a distinct raised "pill" (`borderRadius: 20`, a soft directional shadow) via the shared `Surface` component (`src/presentation/ui/Surface.tsx`); Android keeps a flatter, tighter shadow on the same `surfaceElevated` background. Both now use `boxShadow` (RN 0.86 New Architecture supports it on both platforms) rather than Android's `elevation` — react-doctor's `rn-no-legacy-shadow-styles`/`rn-style-prefer-boxshadow` rules flag `elevation` too, and unlike the tab bar's `getElevatedSurfaceStyle` (still `elevation`-based, unflagged and unchanged), there was no reason left to keep the legacy prop here.

Deliberately out of scope: Material typography (Roboto is already the Android system font) and Material You dynamic colour (fights the fixed brand palette). CMS-flagged `highlighted` destinations now render a small accent-coloured dot on the icon (`TabNavigator` sets a `tabBarHighlighted` option — a `TabOptions` type in `src/navigation/types.ts` riding alongside react-navigation's own options type — and `AppTabBar` draws the dot) instead of the old label-bolding, which had nothing to attach to once the tab bar went icon-only.

Separately, `android/gradle.properties` still had the React Native template's default `edgeToEdgeEnabled=false`, while `targetSdkVersion` is already 36 — Android 15+ enforces edge-to-edge display regardless of that flag, so content was drawing behind the system bars without React Native's inset wiring. Flipped to `true`; `SafeAreaProvider` already wraps the app root and `AppTabBar` reads `insets.bottom`, so this closes the gap rather than opening a new one.

## Consequences
The two platforms share the tab bar's structure and diverge only in material and touch feedback — the opposite of the original decision to visibly diverge the tab bar's layout, revised after prototyping three structural variants and finding the icon-only rail read as more native on both platforms than a bespoke pill. Every interactive element still gives platform-appropriate feedback from one shared component each, rather than per-call-site duplication. The cost is two small native/JS surfaces (`GlassSurface`, `AppTabBar`) to maintain, and a new native dependency (`@react-native-community/blur`) that only iOS uses.
